# Claude Code 超初心者マニュアル

Claude Code（クロードコード）を初めて使う人向けに、「そもそも何なのか」「最低限知っておくべき用語」「実際どう使えばいいのか」をまとめたマニュアルです。

---

## 1. Claude Codeとは何か

**Claude Code**は、Anthropic社が提供する**ターミナル（コマンドライン）上で動くAIコーディングエージェント**です。ひとことで言うと、

> 「あなたのプロジェクトのファイルを実際に読み書きしながら、指示した通りにコードを書いたり直したりしてくれるAI」

です。

### ChatGPT・普通のAIチャットとの違い

| | 普通のAIチャット（ChatGPT等） | Claude Code |
|---|---|---|
| 動く場所 | ブラウザ | パソコンのターミナル（自分のプロジェクトフォルダの中） |
| コードの扱い | コピペしてもらう必要がある | **直接ファイルを読み書き**してくれる |
| 実行できること | 提案のみ | ファイル編集、コマンド実行（テスト実行、git操作等）、複数ファイルにまたがる修正まで自動でこなせる |
| プロジェクトの理解 | 貼り付けた範囲しか見えない | フォルダ内を自分で探索して全体像を把握できる |

つまりChatGPTが「相談相手」だとすると、Claude Codeは「隣に座って実際に手を動かしてくれる（ジュニア）エンジニア」に近いイメージです。

### 何ができるか（代表例）

- バグの原因調査・修正
- 新機能の実装
- 既存コードの説明・レビュー
- テストコードの作成
- リファクタリング
- git操作（コミット・PR作成など）
- コマンド実行（テスト、ビルド、Lint等）

## 2. インストールと起動

### インストール

代表的な方法は次の2つです（どちらもOS問わず公式にサポートされています）。

```bash
# macOS / Linux / WSL の場合
curl -fsSL https://claude.ai/install.sh | bash

# Node.jsが入っている環境なら npm でも可
npm install -g @anthropic-ai/claude-code
```

### 起動方法

1. 作業したいプロジェクトのフォルダに移動する
2. ターミナルで `claude` と入力する

```bash
cd my-project
claude
```

初回はブラウザでログイン（認証）を求められます。認証が終われば、あとはチャット感覚で日本語・英語どちらでも指示を出せます。

他によく使う起動オプション：

```bash
claude -p "このリポジトリの構成を説明して"   # 対話せず1回だけ実行して終了
claude -c                                  # 直前の会話（セッション）を再開
claude -r                                  # 過去のセッション一覧から選んで再開
```

### 初回によくやること：`/init`

プロジェクトフォルダに入って最初にやると良いのが `/init` コマンドです。これはClaude自身にプロジェクトを読み込ませ、後述する `CLAUDE.md` という「プロジェクトの説明書」を自動生成させるコマンドです。

## 3. 最低限おさえておきたい用語集

| 用語 | 説明 |
|---|---|
| **CLAUDE.md** | プロジェクトのルートに置く「Claude用の申し送りメモ」。コーディング規約、よく使うコマンド、注意点などを書いておくと、毎回それを読み込んで動いてくれる。 |
| **スラッシュコマンド（/コマンド）** | `/` から始まる特殊な命令。例：`/init`（初期設定）、`/help`（ヘルプ表示）、`/clear`（会話履歴クリア）、`/compact`（会話を要約して圧縮）、`/model`（使用モデル切り替え）、`/agents`（サブエージェント管理）など。 |
| **ツール（Tool）** | Claudeがファイルやコマンドに対して実際に行動するための機能。代表的なものに `Read`（ファイル読み込み）、`Edit`（部分編集）、`Write`（新規作成・全体書き換え）、`Bash`（コマンド実行）、`Grep`/`Glob`（検索）などがある。 |
| **パーミッション（許可）** | Claudeがファイル編集やコマンド実行など「実際に手を動かす」操作をする前に、ユーザーに確認を求める仕組み。誤操作や意図しない変更を防ぐための安全装置。 |
| **パーミッションモード** | どこまで自動で進めるかの設定。主なモードは「毎回確認する（`default`）」「編集は自動承認する（`acceptEdits`）」「計画だけ立てて実行しない（`plan`）」「ほぼ全操作を自動承認する（`bypassPermissions`、上級者向け）」。 |
| **プランモード（Plan Mode）** | 実際にファイルを変更する前に、まず「どう進めるか」の計画だけを提示させ、ユーザーが承認してから実行に移るモード。`Shift+Tab`で切り替えられる。大きめの変更をする前に安全に方針確認できる。 |
| **サブエージェント（Subagent）** | 特定の作業（コードレビュー、リサーチなど）を専門に任せられる「子エージェント」。メインの会話とは別に独立して作業させ、結果だけ報告してもらうことで、複雑なタスクを整理しながら進められる。 |
| **MCP（Model Context Protocol）** | Claude Codeが外部サービス（GitHub、Slack、データベース等）と連携するための共通規格。「MCPサーバー」を追加することで、Claudeが使えるツールを拡張できる。 |
| **フック（Hooks）** | 「ファイル編集の前後」「コマンド実行前」など特定のタイミングで自動的にスクリプトを実行させる仕組み。Lintの自動実行や独自ルールの強制などに使う（やや上級者向け）。 |
| **コンテキストウィンドウ／オートコンパクト** | Claudeが一度に記憶・参照できる会話量の上限のこと。上限に近づくと自動的に過去の会話を要約して圧縮する（オートコンパクト）ことで、長い作業でも継続できるようにしている。 |
| **セッション** | 1回の起動から終了までの一連の対話のこと。会話を再開したい場合は `claude -c`（直前の会話再開）や `claude -r`（過去のセッション一覧から選んで再開）といった起動オプションがある。 |
| **`/permissions`** | 現在許可されているツールやコマンドの一覧を確認・編集できるスラッシュコマンド。「なぜこの操作が確認を求められたのか」を把握したいときに便利。 |

## 4. 基本的な使い方の流れ

1. **プロジェクトフォルダに移動して起動**
   ```bash
   cd my-project
   claude
   ```
2. **（初回）`/init` を実行**してプロジェクトを把握させ、`CLAUDE.md` を生成する
3. **やってほしいことを日本語で指示する**
   - 例：「`src/auth.py`のログイン処理にあるバグを直して」
4. **Claudeがファイルを読み、修正案を提示・実行しようとする**
   - ファイル編集やコマンド実行の前に「実行してよいですか？」と確認が入る（パーミッション）
5. **内容を確認して承認（または却下）する**
6. **完了したら動作確認**（テスト実行やアプリの起動など）を依頼、または自分で行う
7. **問題なければgitコミットを依頼する**
   - 例：「変更内容をコミットして」

ポイントは、**「丸投げして黙って待つ」のではなく、都度出てくる変更内容や確認を自分の目でチェックしながら進める**ことです。

大きめの変更を頼むときは、`Shift+Tab`でプランモードに切り替えてから指示すると、いきなりファイルが変更される前に「どう進めるか」の計画だけをまず確認できて安心です。

## 5. 初心者向けの実践的な使用例

| やりたいこと | 指示の例 |
|---|---|
| バグ修正 | 「ログイン後にエラーになる不具合を調査して直して」 |
| 新機能追加 | 「商品一覧にページネーションを追加して」 |
| コードの理解 | 「このリポジトリの`src/pipeline`が何をしているか説明して」 |
| テスト作成 | 「`normalize.py`に対するユニットテストを書いて」 |
| リファクタリング | 「この関数、重複が多いので整理して」 |
| git操作 | 「今の変更をわかりやすいコミットメッセージでコミットして」 |
| 実行結果の確認 | 「テストを実行して結果を教えて」 |

最初は「読む・調べる・説明してもらう」といった**安全で元に戻す必要のない依頼**から試すのがおすすめです。

## 6. 初心者向けベストプラクティス

- **具体的に指示する**：「いい感じに直して」より「〇〇の関数で△△のときにエラーになるので直して」の方が精度が上がる
- **小さいタスクに分割する**：大きな変更を一度に頼むより、段階的に依頼したほうが結果を確認しやすい
- **`CLAUDE.md`を育てる**：コーディング規約やよく使うコマンド、注意点を書いておくと、以降の作業精度が上がる
- **危険な操作の前は必ず内容を確認する**：`git push --force`やファイル削除など、元に戻しにくい操作を頼むときは特に慎重に
- **こまめにコミットする**：作業の区切りごとにコミットしておくと、何か問題があっても戻しやすい
- **わからない用語や提案には質問する**：Claudeに「なぜこの実装にしたのか」を聞くのも有効
- **話題が変わったら`/clear`する**：関係のない過去の会話が残っていると精度が落ちやすいので、新しいタスクに移るときはリセットする
- **同じ修正指示を何度も繰り返しても直らない場合は`/clear`して仕切り直す**：状況を整理し直した指示を出すほうが早く解決することが多い

## 7. よくある誤解・注意点

- **「全部自動でやってくれる」わけではない**：重要な判断（設計方針、公開・デプロイの実行など）は基本的に人間が確認・承認する前提で作られている
- **生成されたコードは必ず自分の目でも確認する**：特に本番環境に関わる変更やセキュリティに関わる部分は要チェック
- **料金は基本的にAPI利用量（会話量・処理量）に応じてかかる**：契約プランによって従量課金や月額プランなど形態が異なるため、自分の契約内容を確認しておく
- **万能ではない**：複雑な仕様の理解や、プロジェクト固有の暗黙知が必要な部分は、指示や`CLAUDE.md`での補足が必要になることが多い

---

## 8. まとめ：次の一歩

1. `curl -fsSL https://claude.ai/install.sh | bash`（または`npm install -g @anthropic-ai/claude-code`）でインストール
2. 触ってみたいプロジェクトフォルダで `claude` を起動
3. `/init` でプロジェクトを読み込ませる
4. まずは「このコードを説明して」など軽い依頼から試す
5. 慣れてきたらバグ修正・機能追加・テスト作成など実務的な依頼に挑戦する

わからないことがあれば、Claude Code自身に「〇〇ってどういう意味？」「このコマンド何をするの？」と聞くのが一番の近道です。
