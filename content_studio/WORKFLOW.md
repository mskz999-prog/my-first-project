# カルーセル制作の手順（本人用）

Claude Code に話しかける言葉と、自分で手を動かす作業だけを書いています。
裏側では3つのスキル（vfn-plan → vfn-assets → vfn-publish）が順番に動きます。

| # | 工程 | あなたがやること | Claudeがやること |
|---|---|---|---|
| 1 | 企画 | 「**○○のカルーセル作りたい**」と伝える。参考URLや手描きチャートがあれば一緒に貼る | リサーチして、年代ごとのディテール表を出す |
| 2 | 下書き | 表を見て「**下書きして**」 | 下書きを作る → ファクトチェック担当（サブエージェント）が独立に裏取り → 直した点を報告 |
| 3 | 構成OK | 構成・文言を確認して直したい点を伝える | 修正 |
| 4 | 参考写真 | 「**画像集めて**」。気になる出品URLがあれば貼る | メルカリ・ヤフオク・ブログから**オリジナルだけ**を集めて、出典付きの非公開プレビューを見せる |
| 5 | 写真の差し替え | 「この写真は暗い」など気になる点を伝える | 差し替え |
| 6 | Geminiプロンプト | 「**geminiのプロンプトちょうだい**」 | 番号付きのプロンプト集と添付ファイルを1つのフォルダにまとめて開く |
| 7 | Gemini生成 | Geminiで**新しいチャット**を開き、番号ごとに「添付」欄のファイルを付けてプロンプトを貼る。できた画像を、**番号を書いて**Claudeのチャットに貼る（例：「05」＋画像。何枚まとめてでもOK） | 保存・組み込み → 文字や刻印が正しいか確認 → ページを作り直して見せる。崩れていたら修正プロンプトを出す |
| 8 | 最終版 | 全部そろったら「**最終チェックして**」 | 公開版を作る → 最終チェック担当（サブエージェント）が全ページ点検 → 全ページ見せる |
| 9 | コミット | 「**コミットして**」→ GitHub Desktop で **Push origin** | コミット |
| 10 | 投稿準備 | 「**写真に保存して、キャプションとハッシュタグちょうだい**」 | 写真アプリのアルバム「VFN ○○」に投稿順で保存、キャプションとハッシュタグを出す |
| 11 | 投稿 | スマホの写真アプリにアルバムが同期されたら、Instagramで順番どおりに選んでキャプションを貼って投稿 | — |

## Geminiのコツ（557で分かったこと）
- トピックが変わったら**新しいチャット**で始める（前の絵に引っ張られる）。
- 2回直しても崩れるなら、新しいチャットで「うまくいった画像」を見本として添付してやり直す。
- 2つの年代で見た目が同じ項目（例：フラップ裏）は、同じ絵の使い回しでOK。
- 文字や刻印は崩れやすい。Claudeが貼られた画像をチェックするので、気になる点はそのまま伝えればOK。

## Geminiのコツ（507XXで分かったこと）
- 見本に**別モデルの絵**（例：557の表紙）を添付すると、形までそっくり真似される。表紙は質感見本（ボタンのアップ）＋実物写真だけにする。
- 「〜ではない（サードではない）」と冒頭で明言し、違いを箇条書きにすると形が安定する。
- 一度できた絵の「パーツを動かす」修正（例：袖と胴の隙間を埋める）は、同じチャットでも描き直しでもほぼ直らない。
- のっぺりする時は「マット・乾いた・縦落ち・擦れた白い端」など具体的に。「白い縞」は禁止と書かないと、色落ちを白線で描かれる。

## 困ったとき
- 「今どこまで進んでる？」と聞けば、画像の済／未の一覧を出します。
- Gemini画像は `content_studio/gemini_inbox/` に「05.png」のような名前で置いてもOK（「inboxから取り込んで」と言う）。
